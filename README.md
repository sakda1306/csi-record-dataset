# csi-record-dataset — ระบบบันทึก Wi-Fi CSI dataset

เครื่องมือเก็บ dataset ของโปรเจกต์ **AI-Powered Bathroom Fall Detection System using Wi-Fi Sensing** (ตรวจจับการล้มในห้องน้ำด้วย Wi-Fi CSI)

บันทึกข้อมูล CSI จากบอร์ด Rx (firmware `csi_rx` frame v2) ทีละครั้ง พร้อมป้ายกำกับ (ห้อง, อาสาสมัคร, ท่า) และจังหวะที่ส่งสัญญาณให้ทำท่า ตาม **แผนเก็บข้อมูลเพื่อการตรวจจับการล้มข้ามห้องน้ำ** (`docs/data-collection/Data_Strategy_3_Bathrooms.pdf` ใน repo หลัก)

- **แผนการเก็บ**: ห้องน้ำ A, B (P01-P05) และ C (P06-P07 ทดสอบข้ามห้องเท่านั้น) รอบละ 65 ครั้ง (ล้ม 20 ปกติ 45) + baseline + เคลื่อนไหวอิสระ 20 นาที รวมทั้ง dataset 780 ครั้ง (ล้ม 240 ปกติ 540)
- **จอคอม** (คอมที่เสียบ Rx): ดูสัญญาณแบบ real-time, คุณภาพลิงก์, ตัวเลขนับถอยหลังตัวใหญ่, วิธีทำท่า, แถบเวลา ยืนนิ่ง 0-3 s / ทำท่า 3-6 s / ค้างท่า 6-10 s, จอกะพริบแดงและมีเสียงเมื่อถึงเวลาทำท่า, ผลของแต่ละครั้ง, ความคืบหน้าของรอบตามแผน และของทั้ง dataset
- **มือถือ** = รีโมต: เลือกห้อง อาสาสมัคร และขั้นในแผน แล้วกดเริ่ม / หยุด / เก็บ / บันทึกใหม่ มือถือสั่นและมีเสียงตอนให้ทำท่า (มือถือ Android สั่นได้ ส่วน iPhone ไม่สั่น)
- ค่าทั้งหมดอยู่ใน `config.toml` เช่น พอร์ต, เวลา, เกณฑ์คุณภาพ, ห้อง, ท่า และลำดับของรอบ

ใช้ได้ทั้ง Windows และ macOS ไม่ต้องลงโปรแกรมอื่นเพิ่ม และไม่ต้องใช้อินเทอร์เน็ต หน้าเว็บทั้งหมดอยู่ในโฟลเดอร์นี้

## สิ่งที่ต้องมี

| อุปกรณ์ / โปรแกรม | รายละเอียด |
|---|---|
| บอร์ด Tx | ESP32-S3 ที่ flash firmware `csi_tx` แล้ว (ส่ง ping 100 Hz) ใช้ไฟจาก power bank ได้ |
| บอร์ด Rx | ESP32-S3 ที่ flash firmware `csi_rx` แล้ว (serial frame v2, 921600 baud) เสียบ USB เข้าคอม |
| คอม | Windows หรือ macOS ที่มี Python 3.11 ขึ้นไป |
| มือถือ | เบราว์เซอร์อะไรก็ได้ ต่อ Wi-Fi วงเดียวกับคอม |

## เริ่มต้นเร็ว

```bash
git clone https://github.com/sakda1306/csi-record-dataset.git
cd csi-record-dataset
pip install -r requirements.txt          # pyserial, numpy  (macOS: pip3)
```

แล้วเปิด `config.toml` เพื่อแก้อย่างน้อย 3 อย่าง:

1. `[storage] data_dir`: โฟลเดอร์เก็บ dataset ของเครื่องคุณ ค่าในไฟล์ตอนนี้เป็น Google Drive ของเครื่องผู้พัฒนา ดูวิธีเขียน path ที่หัวข้อ [เปลี่ยนโฟลเดอร์เก็บ dataset](#เปลี่ยนโฟลเดอร์เก็บ-dataset)
2. `[server] pin`: เปลี่ยนจาก `1234` เป็นรหัสของคุณเอง
3. `[[rooms]] setup`: จดขนาดห้องและระยะ Tx-Rx จริงของแต่ละห้อง (บันทึกลงทุกไฟล์ของห้องนั้น)

จากนั้นรัน `python record.py` (macOS: `python3 record.py`)

## ใช้งาน

```bash
python record.py
```

1. โปรแกรมหาบอร์ด Rx ให้เอง (`rx_port = "auto"`) แล้วเปิดหน้าจอแสดงผลในเบราว์เซอร์ **คลิกบนหน้าจอหนึ่งครั้งเพื่อเปิดเสียง**
2. ในเทอร์มินัลจะมีที่อยู่สำหรับมือถือ เช่น `http://192.168.1.45:8765/m` ที่อยู่เดียวกันนี้แสดงที่มุมขวาบนของจอคอมด้วย พร้อม **QR code** (กดเพื่อขยาย) สแกนด้วยกล้องมือถือแล้วเข้าหน้ารีโมตได้เลยโดยไม่ต้องใส่ PIN เพราะ QR มี PIN อยู่ในตัว ใครเห็นจอคอมก็สั่งงานได้ รูป QR นี้เปิดได้เฉพาะจากคอมเครื่องนี้
3. มือถือต้องต่อ **Wi-Fi วงเดียวกับคอม** เปิดที่อยู่นั้น แล้วใส่ PIN (ค่าเริ่มต้น `1234`)
4. บนมือถือ: เลือก **ห้องน้ำ** (A/B/C) และ **อาสาสมัคร** (ห้อง + อาสาสมัคร = 1 รอบ) แล้วแตะขั้นในแผน จำนวนครั้งจะใส่เป็นจำนวนที่เหลือของขั้นนั้นให้เอง กด **เริ่ม** จบขั้นแล้วระบบเลือกขั้นถัดไปให้
5. แผน 1 รอบ (ตาม §7 ของเอกสาร):

| ขั้น | ท่า | ครั้ง | วิธีทำ |
|---|---|---|---|
| 1 | ห้องว่าง (baseline) 60 s | 1 | วางเบาะแล้ว ทุกคนออกจากห้อง (นับถอยหลัง 15 s) |
| 2 | ล้มไปข้างหน้า ชุดที่ 1 (fall) | 10 | ลงเข่าก่อน ตามด้วยมือ ลงบนเบาะ แล้วนอนนิ่ง · แล้วพัก 3 นาที |
| 3 | นั่งลงแล้วลุกขึ้น | 10 | นั่งบนเก้าอี้ที่มั่นคง แล้วลุกขึ้น |
| 4 | ก้มเก็บของ | 10 | ก้มเก็บของจากพื้น แล้วยืดตัวขึ้น · แล้วพัก 3 นาที |
| 5 | ล้มไปข้างหน้า ชุดที่ 2 (fall) | 10 | เหมือนขั้น 2 · แล้วพัก 3 นาที |
| 6 | เดินแล้วหยุดยืน | 10 | เดินในห้อง แล้วหยุดยืนนิ่ง |
| 7 | ค่อยๆ นั่งหรือนอนลง | 10 | ลงสู่พื้นช้าๆ ระบบสลับ นั่ง / นอน ให้เอง (นั่ง 5 นอน 5) |
| 8 | ท่าคล้ายอาบน้ำ | 5 | ยกแขนถูตัวและสระผม ทำแบบแห้ง |
| 9 | เคลื่อนไหวอิสระ (ไม่ล้ม) | 10 x 2 นาที | 20 นาที ไม่นำไปฝึก ใช้วัดการแจ้งเตือนผิดต่อชั่วโมง |

6. แต่ละครั้งเป็นแบบนี้ (§6):

```
นับถอยหลัง 5 s ──► บันทึก 10 s ──────────────────────────────────────►  ตรวจคุณภาพ ──► พัก 15 s ──► ครั้งถัดไป
   (เข้าที่)         0-3 s ยืนนิ่ง │ 3 s สัญญาณ "ล้ม!" ทำท่า │ 6-10 s ค้างท่าสุดท้าย
                                    (เสียง 3 ครั้ง + จอแดง)
```

7. ครั้งที่ **ผ่าน** ถูกเก็บอัตโนมัติ ส่วนครั้งที่ **ไม่ผ่าน** หรือ **ผ่านแต่มีคำเตือน** (เช่น ขยับก่อนสัญญาณ, ท่ายังไม่จบตอนหยุดบันทึก) ระบบจะรอให้เลือก **เก็บ / ทิ้งแล้วบันทึกใหม่ / ทิ้งแล้วหยุด** (บันทึกใหม่ในรอบเดียวกัน)
8. ถ้ายังไม่ได้บันทึก baseline ของรอบนั้น ทั้งสองจอจะเตือน
9. เลิกใช้งานให้กด `Ctrl+C` ในเทอร์มินัล

**ปุ่มลัดบนจอคอม:** `K` เก็บ, `R` บันทึกใหม่, `D` ทิ้ง, `Esc` หยุด คำสั่งที่ส่งจากคอมเครื่องนี้เองไม่ต้องใส่ PIN

**ห้องว่าง (baseline):** ขั้นแรกของทุกรอบ วางเบาะแล้วทุกคนออกจากห้องและปิดประตูระหว่างนับถอยหลัง 15 วินาที ไฟล์อยู่ในโฟลเดอร์ของอาสาสมัครรอบนั้น (เช่น `p01/a_p01_baseline_01.bin`) และทุกครั้งต่อจากนั้นของรอบจะอ้างถึงไฟล์นี้ใน `baseline_file`

### เสียงที่ได้ยิน

| เสียง | ความหมาย |
|---|---|
| ติ๊ด 3 ครั้ง (ต่ำ) | อีก 3, 2, 1 วินาทีเริ่มบันทึก |
| ปี๊ด (สูง ยาว) | เริ่มบันทึกแล้ว อยู่นิ่ง |
| ปี๊ดๆๆ (สูงมาก 3 ครั้ง) + จอแดง | **ทำท่าเลย** |
| ปู๊-ปู้ (ลงต่ำ) | จบครั้ง |

เสียงทุกตัวเล่นตามเวลาที่เซิร์ฟเวอร์กำหนดไว้ล่วงหน้า จึงตรงกับเวลา cue ที่บันทึกในไฟล์ (คลาดเคลื่อนไม่กี่มิลลิวินาทีบนจอคอม)

## ไฟล์ที่ได้

### เปลี่ยนโฟลเดอร์เก็บ dataset

แก้ `[storage] data_dir` ใน `config.toml` ถ้าโฟลเดอร์ยังไม่มี โปรแกรมจะสร้างให้เอง และตอนเปิดโปรแกรมจะลองเขียนไฟล์ดูก่อน ถ้าเขียนไม่ได้ (เช่น ไม่มีไดรฟ์นั้น) จะแจ้งทันที ไม่รอจนบันทึกครั้งแรก โฟลเดอร์ที่ใช้อยู่แสดงที่หัวจอคอม (📁)

```toml
data_dir = "data"                               # ค่าเริ่มต้น: โฟลเดอร์ data ข้างไฟล์ config
data_dir = "D:/Dataset/CSI"                     # Windows: ใช้ / ได้
data_dir = 'D:\Dataset\CSI'                     # Windows: ถ้าจะใช้ \ ต้องใช้ ' ไม่ใช่ "
data_dir = "~/Documents/CSI-dataset"            # macOS
data_dir = "G:/My Drive/Final-Project/dataset"  # Google Drive ที่ sync ไว้ = สำรองอัตโนมัติ
```

ห้ามเขียน `"D:\Dataset"` (`\` ใน `"..."`) เพราะ TOML ถือว่า `\` เป็นตัวพิเศษ (`"D:\new"` จะกลายเป็นขึ้นบรรทัดใหม่) ถ้าเขียนแบบนี้ โปรแกรมจะแจ้งพร้อมบอกวิธีแก้

ในโฟลเดอร์นั้น ไฟล์จะแยกตาม `session` (ค่าเริ่มต้นคือวันที่) และอาสาสมัคร ตาม §9 ของแผน:

```
<data_dir>/
├─ labels.csv                         ป้ายกำกับของทั้ง dataset 1 แถวต่อครั้งที่เก็บ (ใช้แบ่ง train/val/test)
└─ <session>/
   ├─ manifest.csv                    ทุกครั้งที่เก็บของ session นี้ + ค่าคุณภาพ
   ├─ p01/
   │  ├─ a_p01_baseline_01.bin        ห้องว่างของรอบ A · p01
   │  ├─ a_p01_fall_01.bin            ข้อมูลดิบ ทุกเฟรมตามที่ Rx ส่งมา (frame v2, มี phase ครบ)
   │  ├─ a_p01_fall_01.csv            amplitude 64 subcarrier: Timestamp, RSSI, Sub_0..Sub_63 (หัวตารางเดียวกับ exp7/exp8)
   │  └─ a_p01_fall_01.json           ป้ายกำกับ + เวลา cue + เวลาท่า + คุณภาพ + ข้อมูลห้องและบอร์ด
   └─ _discarded/                     ครั้งที่กดทิ้ง (ไม่ได้ลบจริง)
```

- ชื่อไฟล์ = `<ห้อง>_<อาสาสมัคร>_<ท่า>_<ครั้งที่>` เลขครั้งที่นับต่อจากที่เก็บไว้แล้ว แม้จะเก็บต่อคนละวัน (วันสำรอง)
- **`labels.csv`** มีคอลัมน์ตามแผน: `file, room, volunteer, action, label, trial, action_start_s, action_end_s, baseline_file, note`
  - `file` และ `baseline_file` เป็น path นับจาก `data_dir` เช่น `2026-12-22/p01/a_p01_fall_01.bin`
  - `label`: `fall` / `normal` และ `none` สำหรับห้องว่าง (ไม่ใช่คลาส) ส่วนเคลื่อนไหวอิสระมี note `ไม่ใช้ฝึก`
  - `action_start_s`, `action_end_s` = วินาทีที่ท่าเริ่มและจบจริง **ประมาณจากการเคลื่อนไหวใน CSI** (ช่วงละ 0.25 s) ไม่ใช่การจดด้วยมือ ถ้าต้องการแก้ ให้แก้ในไฟล์นี้ได้เลย
  - ห้อง C ใช้ทดสอบข้ามห้องเท่านั้น ตอนแบ่งข้อมูลห้ามเอาไปฝึก
- **`.json`** ที่สำคัญ: `room`, `room_setup`, `test_only`, `label`, `activity`, `volunteer`, `people_in_room`, `trial`, `cue.offset_s` (วินาทีที่ให้สัญญาณ นับจากต้นไฟล์), `cue.csv_row` (แถวใน CSV ณ เวลานั้น), `action_start_s/end_s`, `baseline_file`, `quality.*`, `device.rx_mac`
- **`.bin`** อ่านได้ด้วย `csirec.csi_serial.FrameReader` (ตัวเดียวกับใน `firmware/tools` ของ repo):

```python
from csirec.csi_serial import FrameReader

frames, _ = FrameReader().feed(open("p01/a_p01_fall_01.bin", "rb").read())
```

- ถ้า `manifest.csv` ของ session เดิมเป็นแบบเก่า (มีคอลัมน์ `position`) โปรแกรมจะเปลี่ยนชื่อไฟล์เก่าเป็น `manifest_old_<เวลา>.csv` แล้วเริ่มไฟล์ใหม่ ไม่ลบของเดิม

- CSV ตัดเฟรมที่ส่งซ้ำ (retry) ออกแล้ว Timestamp คำนวณจากนาฬิกาของ Rx จึงแม่นระดับเฟรม ไม่ใช่เวลาที่ serial อ่านได้

## เกณฑ์คุณภาพ (ตั้งใน `[quality]`)

| ตรวจ | ค่าเริ่มต้น | ไม่ผ่านเมื่อ |
|---|---|---|
| อัตราเฟรม | 80 Hz (ประมาณ 1,000 ตัวอย่าง หายไม่เกิน 20 % ตาม §6) | ต่ำกว่า |
| เฟรมหายในอากาศ (จาก `rx_seq`) | 20 % | เกิน |
| สัญญาณขาดช่วงนานสุด (นับตั้งแต่ต้นถึงท้ายครั้ง) | 200 ms | เกิน |
| checksum ผิด | 0 | มีแม้แต่ครั้งเดียว |
| การเคลื่อนไหวหลังสัญญาณ ÷ ก่อนสัญญาณ | 2.0 เท่า | **เตือน** ว่าอาจทำท่าไม่ทันจังหวะ |
| เริ่มขยับก่อนสัญญาณเกิน 0.5 s | | **เตือน** |
| ยังขยับอยู่ในช่วง 0.5 s สุดท้าย (ท่าไม่ครบในช่วงบันทึก) | ยกเว้นท่าที่ `ends_still = false` | **เตือน** |

คำเตือนไม่ทำให้ไม่ผ่าน แต่ถ้า `review_warnings = true` (ค่าเริ่มต้น) ครั้งนั้นจะรอให้กดเก็บหรือบันทึกใหม่ก่อน

## `config.toml`

ทุกค่ามีคอมเมนต์ภาษาไทยอธิบายไว้ในไฟล์ ค่าที่ใช้บ่อย:

| อยากเปลี่ยน | แก้ที่ |
|---|---|
| พอร์ต Rx | `[serial] rx_port` เช่น `"COM10"` หรือ `"/dev/cu.usbserial-0001"` |
| เวลาบันทึก / นับถอยหลัง / จังหวะทำท่า / พัก | `[timing]` (ทุกท่า) หรือใส่ในแต่ละ `[[activities]]` (เฉพาะท่านั้น) |
| PIN, พอร์ตเว็บ | `[server] pin`, `port` |
| **โฟลเดอร์เก็บ dataset**, ชื่อ session, สถานที่ | `[storage] data_dir` (ดู "เปลี่ยนโฟลเดอร์เก็บ dataset"), `session`, `location` |
| ห้องน้ำ, อาสาสมัครของแต่ละห้อง, ขนาดห้อง/ระยะติดตั้ง | `[[rooms]]` `volunteers`, `setup`, `test_only` |
| เพิ่ม/ลบท่า, วิธีทำท่า | `[[activities]]` `name`, `desc` |
| ลำดับและจำนวนครั้งใน 1 รอบ (เช่น หลังทดลองนำร่อง) | `[[steps]]` `activity`, `reps`, `break_min` |
| เกณฑ์ผ่าน, เก็บอัตโนมัติ | `[quality]` |
| ปิดเสียง / เสียงพูด / สั่น | `[cue]` |

ถ้าพิมพ์ชื่อค่าผิด หรือวางค่าไว้ผิดหัวข้อ โปรแกรมจะแจ้งตอนเปิด ไม่ข้ามค่านั้นไปเฉยๆ (ใน TOML ทุกบรรทัดที่อยู่ใต้ `[หัวข้อ]` เป็นของหัวข้อนั้นจนกว่าจะเจอหัวข้อถัดไป)

ใช้ config คนละไฟล์ได้: `python record.py --config mac.toml`

## แก้แผนจากหน้าเว็บ (ห้อง ท่า ขั้น นอกแผน PDF)

ค่าเริ่มต้นคือแผน PDF ใน `config.toml` (ห้อง A B C, 9 ขั้น, 65 ครั้งต่อรอบ, เป้า 780) ถ้าอยากเก็บเพิ่ม
เช่น ห้องน้ำ D หรือท่าล้มไปข้างหลัง ให้กดปุ่ม **แก้แผน** มุมบนของหน้าจอคอม (หรือเปิด `http://127.0.0.1:8765/plan`)

| ทำได้ | หมายเหตุ |
|---|---|
| เพิ่มห้อง | ใช้ลำดับขั้นเดียวกับแผน ยอดทั้งหมดของห้องนี้นับเป็น "นอกแผน" |
| เพิ่มท่า (เช่น ล้มไปข้างหลัง) | ตั้งประเภท ล้ม/ปกติ เวลา และวิธีทำท่าได้ |
| เพิ่มขั้นท้ายรอบ, เลื่อนลำดับ ↑ ↓ | ขั้นของแผน PDF ล็อกไว้ ขั้นที่เพิ่มต่อท้าย |
| ปรับเวลานับถอยหลัง / สัญญาณ / พัก ของท่าในแผน PDF | ความยาวการบันทึก 10 s ของท่าในแผนล็อกไว้ |
| ซ่อนห้องหรือท่าที่เพิ่ม | ปุ่มหายจากมือถือ แต่ข้อมูลที่เก็บแล้วยังอยู่ |
| ลบห้องหรือท่าที่เพิ่ม | ลบได้เฉพาะที่ยังไม่มีข้อมูล ถ้ามีแล้วให้ซ่อนแทน |

- กด **บันทึกแผน** แล้วหน้าจอคอมและมือถือเปลี่ยนตามทันที ไม่ต้องเปิดโปรแกรมใหม่ (แก้ได้เฉพาะตอนไม่ได้บันทึก)
- ส่วนที่เพิ่มเก็บใน `plan-extra.json` ข้างโฟลเดอร์ dataset (`[storage] data_dir`) ไม่แก้ `config.toml`
  ถ้า dataset อยู่ใน Google Drive ทุกเครื่องที่ใช้โฟลเดอร์เดียวกันจะได้แผนเดียวกัน
- ครั้งที่เกินเป้าแผน PDF หรืออยู่นอกแผน ได้หมายเหตุ `นอกแผน` ใน `labels.csv` และแสดงแยกในการ์ด "นอกแผน" บนหน้าจอคอม
  ไม่นับรวมเป้า 65/780
- **กลับไปใช้แผน PDF**: กดสองครั้ง ไฟล์แผนเดิมถูกเปลี่ยนชื่อเป็น `plan-extra_old_<เวลา>.json` (ไม่ลบ) ข้อมูลที่เก็บแล้วอยู่ครบ
- ถ้า `plan-extra.json` เสีย โปรแกรมยังเปิดได้ด้วยแผน PDF และแจ้งในบันทึกเหตุการณ์

## ย้ายไปเครื่องอื่น (เช่น MacBook ของเพื่อน)

1. `git clone https://github.com/sakda1306/csi-record-dataset.git` (หรือคัดลอกโฟลเดอร์ไปทั้งโฟลเดอร์)
2. `pip3 install -r requirements.txt`
3. เสียบ Rx แล้วรัน `python3 record.py --list-ports` เพื่อดูชื่อพอร์ต ปล่อยเป็น `"auto"` ก็ได้ เพราะบน Mac โปรแกรมเลือกเฉพาะพอร์ต `/dev/cu.*` ให้อยู่แล้ว
4. ถ้า auto หาไม่เจอ ให้ใส่ชื่อพอร์ตใน `config.toml` หรือรัน `python3 record.py --port /dev/cu.usbserial-0001`

บน Mac การเปิดพอร์ตอาจทำให้ Rx รีเซ็ตหนึ่งครั้ง รอประมาณ 10 วินาทีให้ Rx จับคู่กับ Tx ใหม่ จนแถบด้านบนเป็นสีเขียว

## ปัญหาที่พบบ่อย

| อาการ | ทำอย่างไร |
|---|---|
| มือถือเปิดหน้าไม่ขึ้น | (1) มือถืออยู่ Wi-Fi วงเดียวกับคอมไหม (2) **ไฟร์วอลล์**: ครั้งแรกที่รัน Windows จะถามเรื่อง Python ให้กด **Allow** สำหรับ Private network ส่วน macOS ให้กด **Allow incoming connections** (3) Wi-Fi มหาวิทยาลัยมักกั้นไม่ให้อุปกรณ์มองเห็นกัน ให้เปิด **hotspot จากมือถือ** แล้วให้คอมต่อ hotspot นั้น จากนั้นใช้ที่อยู่ใหม่ที่เทอร์มินัลแสดง |
| ไม่มีเสียงบนจอคอม | คลิกบนหน้าจอหนึ่งครั้ง (เบราว์เซอร์บังคับ) และเช็กว่า `[cue] sound = true` |
| ไม่มีเสียงพูดชื่อท่า | เครื่องไม่มีเสียงภาษาไทยในเบราว์เซอร์ ไม่กระทบการบันทึก จะปิดก็ได้ด้วย `speech = false` |
| "ไม่เจอบอร์ด Rx" | Tx ต้องเปิดอยู่ด้วย เพราะ auto ดูว่าพอร์ตไหนมีข้อมูล CSI ไหลอยู่ หรือใส่ชื่อพอร์ตเอง |
| "เปิดพอร์ตไม่ได้" | มีโปรแกรมอื่นใช้พอร์ตอยู่ เช่น Arduino Serial Monitor หรือ `csi_live.py` ให้ปิดโปรแกรมนั้นก่อน |
| แถบสถานะแดง ระหว่างบันทึก | ครั้งนั้นจะไม่ผ่านเอง ให้เช็กไฟ Tx และระยะ แล้วกดบันทึกใหม่ |
